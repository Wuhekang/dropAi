# Professional asset and slide priorities

Use the source document only. Classify uncertain images as `OTHER` and leave them unassigned instead of inventing meaning.

| Major | Preferred assets | Preferred slide treatment |
|---|---|---|
| Computer / software | architecture, UML, ER, UI screenshot, test result | architecture as large image; implementation screenshots one per slide; tests as data |
| Mechanical | CAD, 3D model, engineering drawing, exploded view, parameter table | model/drawing at 70%; parameters as data |
| Environmental / landscape | location, site analysis, plan, aerial view, rendering | analysis image-led; plan/rendering at 70% |
| Interior | spatial analysis, floor plan, rendering, material board | floor plan and each core rendering on separate slides |
| Visual communication | logo, poster, key visual, application mockup | artwork-led, one core outcome per slide |
| UI design | user flow, wireframe, interface, design system | flow as image-text; interface one screen group per slide |
| Digital media | storyboard, scene, interaction flow, final frame | sequence pages only when source order is explicit |

Map source wording to these types; do not infer factual image content from filenames alone.
